## Task 1: المقدمة (Introduction)

### ما هو Snort ولماذا نستخدمه؟
**Snort** هو نظام مفتوح المصدر يعتمد على القواعد (Rule-based) لاكتشاف ومنع الاختراقات على مستوى الشبكة (**NIDS/NIPS**). قام بتطويره **Martin Roesch** ويُطوَّر حاليًا بواسطة مجتمع المصادر المفتوحة وفريق **Cisco Talos**.

**الفكرة الأساسية وراء استخدامه:**
يقوم Snort بفحص حزم البيانات (Packets) في الشبكة لحظيًا أو من خلال ملفات مسجّلة (`.pcap`)، ومطابقتها مع قواعد يكتبها محللو الأمن السيبراني لتحديد الأنشطة الخبيثة:
- إذا عمل كـ **IDS**: يُطلق **تنبيهًا (Alert)** ويسجّل الحزمة فقط.
- إذا عمل كـ **IPS**: يتدخل بشكل فعلي **ويمنع أو يُسقط (Drop/Reject)** الاتصال الخبيث فور اكتشافه.

### أهداف الغرفة
1. فهم الفرق بين أنظمة IDS و IPS وأنواعها.
2. التعرف على أوضاع تشغيل Snort وأهم الـ Flags.
3. تعلم كيفية كتابة Snort Rules مخصصة من الصفر.
4. التدرب على اكتشاف الاختراقات وتحليل الترافيك الحي وملفات الـ PCAP.

## Task 3: مقدمة في أنظمة IDS و IPS

قبل كتابة أوامر Snort، يجب أن نعرف الفرق بين **الاكتشاف (Detection)** و**المنع (Prevention)**، وأين يعمل كل نظام، وكيف يكتشف الهجمات.

### 1. نظام كشف التسلل — Intrusion Detection System (IDS)
حل **سلبي (Passive)** يراقب الترافيك ويكتشف الأنشطة المشبوهة أو مخالفات السياسات ويولّد **تنبيهات (Alerts)** فقط (يحتاج لتدخل بشري أو نظام آخر لإيقاف الهجوم):
- **NIDS (Network IDS):** يراقب الترافيك عبر نقاط متعددة في الشبكة لحماية/فحص **الشبكة الفرعية بالكامل (Subnet)**.
- **HIDS (Host-based IDS):** يراقب الترافيك والنشاط على **جهاز واحد فقط (Endpoint)**.

### 2. نظام منع التسلل — Intrusion Prevention System (IPS)
حل **نشط (Active)** يراقب الترافيك ويقوم فورًا **بإيقاف أو إنهاء الاتصال** بمجرد اكتشاف التهديد:
- **NIPS (Network IPS):** يراقب ترافيك الشبكة بالكامل ويقطع الاتصال عند تطابق التوقيع الخبيث (Signature).
- **Behaviour-based IPS / NBA (Network Behaviour Analysis):** يراقب الشبكة ويكتشف **الشذوذ (Anomalies)** عن السلوك الطبيعي ثم يقطع الاتصال.
  - **أهم ميزة فيه:** يكتشف التهديدات **الجديدة وغير المعروفة** التي لم يُكتب لها Signature بعد.
  - **فترة التدريب (Baselining):** يحتاج NBA أولًا إلى فترة تدريب تُسمى **Baselining** ليتعلم شكل الترافيك الطبيعي. **تحذير مهم:** حدوث اختراق أثناء فترة التدريب يفسد القاعدة المرجعية للنظام، والتدريب الضعيف يؤدي لكثرة الإنذارات الكاذبة (False Positives).
- **WIPS (Wireless IPS):** مخصص لمراقبة الشبكات اللاسلكية وإيقاف الهجمات القادمة عبرها.
- **HIPS (Host-based IPS):** يعمل على **جهاز واحد فقط** مثل HIDS، لكن الفارق أن HIPS يمنع التهديد ويقطع الاتصال بدل الاكتفاء بالتنبيه.

### 3. تقنيات الكشف والمنع (Detection/Prevention Techniques)

| التقنية | آلية العمل | الفائدة الأساسية |
| :--- | :--- | :--- |
| **Signature-Based** | تعتمد على قواعد وتواقيع لأنماط هجمات معروفة مسبقًا. | اكتشاف **التهديدات المعروفة** بدقة وسرعة. |
| **Behaviour-Based** | تقارن السلوك الطبيعي المُتعلَّم بالسلوك غير المعتاد. | اكتشاف **التهديدات الجديدة والمجهولة** التي تتجاوز التواقيع. |
| **Policy-Based** | تقارن الأنشطة المرصودة بإعدادات النظام والسياسات الأمنية. | اكتشاف **مخالفات السياسات الأمنية**. |

### 4. نظرة عامة على Snort وأوضاع تشغيله الثلاثة
- **إمكانات Snort:** تحليل الترافيك الحي، كشف الهجمات والفحص (Probes)، تسجيل الحزم، تحليل البروتوكولات، التنبيه اللحظي، دعم الوحدات والإضافات (Modules & Plugins)، المعالجات المسبقة (Pre-processors)، والعمل على Linux وWindows.
- **أوضاع التشغيل الأساسية:**
  1. **Sniffer Mode:** قراءة وعرض حزم IP مباشرة على الشاشة مثل `tcpdump`.
  2. **Packet Logger Mode:** تسجيل جميع حزم IP (الواردة والصادرة) على القرص الصلب للرجوع إليها لاحقًا.
  3. **NIDS / NIPS Mode:** فحص الحزم مقابل قواعد محددة للتنبيه والتسجيل (IDS) أو الحجب والإسقاط (IPS).

## Task 4: أول تعامل مع Snort

### ماذا فعلنا ولماذا نستخدم هذه الـ Flags؟
قبل بدء أي مراقبة، نحتاج للتأكد من أن Snort مثبّت ويعمل، وأن ملف الإعدادات (`snort.conf`) خالٍ من الأخطاء.

| الـ Flag | وظيفته | ما فائدته العملية؟ |
| :--- | :--- | :--- |
| `-V` / `--version` | عرض نسخة Snort | يوضح الإصدار، **رقم البناء (Build)**، وإصدارات المكتبات (`libpcap`, `PCRE`, `ZLIB`) للتأكد من التوافق قبل تحميل القواعد. |
| `-c <file>` | تحديد ملف الإعدادات | يوجّه Snort لاستخدام ملف إعدادات معين مثل `/etc/snort/snort.conf`. يمكنك امتلاك عدة ملفات إعدادات لأغراض مختلفة، لكن يُستخدم ملف واحد فقط في كل مرة تشغيل. |
| `-T` | وضع الاختبار الذاتي (Test) | يفحص صحة ملف الإعدادات، المعالجات، القواعد، ويعرض عدد القواعد المحمّلة **دون بدء التقاط فعلي**. ضروري قبل تشغيل أي تعديل على البيئة الحقيقية. |
| `-q` | الوضع الصامت (Quiet) | يخفي شعار Snort الافتراضي ورسائل التهيئة الطويلة، مما يجعل المخرجات نظيفة وسهلة القراءة أو المعالجة في السكربتات. |

#### الأوامر المستخدمة
```bash
# 1. معرفة إصدار Snort ورقم الـ Build
snort -V

# 2. اختبار ملف الإعدادات الرئيسي ومعرفة عدد القواعد المحملة
sudo snort -c /etc/snort/snort.conf -T

# 3. اختبار ملف الإعدادات الثاني ومقارنة عدد القواعد
sudo snort -c /etc/snort/snortv2.conf -T
```

> **لماذا نستخدم `sudo` مع `-T`؟** لأن ملفات القواعد ومسارات النظام غالبًا محمية بصلاحيات root، وتشغيل الاختبار بـ `sudo` يضمن عدم فشل قراءة أي ملف مُدرج.

### الأسئلة والإجابات

| السؤال | كيف حصلنا على الإجابة؟ | الإجابة |
| :--- | :--- | :--- |
| Run the Snort instance and check the build number. | من مخرجات `snort -V` يظهر السطر `Version 2.9.7.0 GRE (Build 149)`. | `149` |
| Test the current instance with `/etc/snort/snort.conf` file and check how many rules are loaded with the current build. | من مخرجات `sudo snort -c /etc/snort/snort.conf -T` يظهر إجمالي القواعد المحمّلة. | `4151` |
| Test the current instance with `/etc/snort/snortv2.conf` file and check how many rules are loaded with the current build. | من مخرجات `sudo snort -c /etc/snort/snortv2.conf -T` يظهر تحميل قاعدة واحدة فقط. | `1` |

## Task 5: وضع التشغيل الأول — Sniffer Mode

### ما هو هذا الوضع ومتى يفيدنا؟
في وضع **Sniffer Mode** يعمل Snort تمامًا كأداة `tcpdump`؛ يلتقط الحزم من كارت الشبكة ويعرضها مباشرة في الطرفية دون الحاجة لملف إعدادات أو قواعد.
**ما فائدته؟** ممتاز في التشخيص السريع (Troubleshooting)، والتأكد من وصول الترافيك لكارت الشبكة، ومعاينة الترويسات (Headers) ومحتوى الحزم (Payload) لحظيًا.

### شرح كل Flag في Sniffer Mode

| الـ Flag | ماذا يعرض؟ | متى ولماذا نستخدمه؟ |
| :--- | :--- | :--- |
| `-i <iface>` | تحديد واجهة الشبكة (مثل `eth0`) | ضروري إذا كان الجهاز يحتوي على أكثر من كارت شبكة لتحديد الكارت المطلوب التنصت عليه. (إذا كان هناك كارت واحد فقط يختاره Snort تلقائيًا). |
| `-v` | وضع التفصيل (Verbose) | يعرض ترويسات TCP/IP (العناوين، البورتات، TTL، IP ID، طول الحزمة) بدون إغراق الشاشة ببيانات الـ Payload. |
| `-d` | عرض محتوى البيانات (Payload) | يضيف بيانات طبقة التطبيق (مثل نص طلبات HTTP أو استعلامات DNS) بصيغتي Hex و ASCII مع المعلومات الأساسية. |
| `-e` | عرض ترويسات طبقة الربط (Link-Layer / Ethernet) | يُظهر عناوين الـ **MAC** (المرسل والمستقبل) ونوع الإطار (`0x800`) وحجمه. مفيد عند تتبع مشاكل الشبكة المحلية أو ARP. |
| `-X` | تفريغ كامل للحزمة بالـ HEX و ASCII | يعرض **كل بايت** في الحزمة بدءًا من طبقة Ethernet حتى نهاية البيانات (`0x0000: ...`). يمنحك أقصى درجة رؤية ممكنة للحزمة. |

#### أمثلة عملية للجمع بين الـ Flags
```bash
sudo snort -v -i eth0    # عرض ترويسات TCP/IP على واجهة eth0
sudo snort -v            # عرض الترويسات على الواجهة الافتراضية
sudo snort -d            # عرض الترويسات + بيانات الـ Payload
sudo snort -de           # إضافة عناوين الـ MAC (نفس: snort -d -e)
sudo snort -X            # عرض الحزمة كاملة بالـ HEX و ASCII
```

> **معلومة مفيدة:** يمكنك دمج الفلاجز (`-de`) أو فصلها (`-d -e`)، وعند الضغط على `CTRL+C` يتوقف Snort ويعرض ملخصًا إحصائيًا للحزم التي التقطها.

## Task 6: وضع التشغيل الثاني — Packet Logger Mode

### ما هو هذا الوضع ولماذا نستخدمه؟
عرض الحزم على الشاشة فقط يجعلها تختفي بسرعة مع كثرة الترافيك. لذلك يأتي وضع **Packet Logger Mode** ليحفظ الحزم على القرص الصلب، مما يفيد في التحليل الهادئ لاحقًا، أو حفظ الأدلة الجنائية (Forensics)، أو فتح السجلات لاحقًا في Snort أو Wireshark أو `tcpdump`.

### شرح كل Flag في Logger Mode

| الـ Flag | الوظيفة | ما فائدته العملية؟ |
| :--- | :--- | :--- |
| `-l <dir>` | تحديد مجلد حفظ السجلات والتنبيهات | المجلد الافتراضي هو `/var/log/snort`. تمرير `-l .` يجعل Snort يحفظ السجلات داخل **المجلد الحالي**، وهو مثالي لتنظيم ملفات كل تمرين أو حادثة على حدة. |
| *(الوضع الثنائي الافتراضي)* | حفظ ملف واحد بصيغة binary مثل `snort.log.<timestamp>` | سريع في الكتابة وصغير الحجم ومتوافق مع `snort -r` و`tcpdump` و`Wireshark`، لكنه غير قابل للقراءة المباشرة كملف نصي. |
| `-K ASCII` | حفظ السجلات بصيغة نصية مقروءة داخل مجلدات حسب الـ IP | ينشئ مجلدًا لكل IP وبداخله ملفات مصنفة حسب البروتوكول والبورت (مثل `UDP:3009-53`). سهل القراءة بأي محرر نصوص، **لكن** لا يمكن قراءته لاحقًا باستخدام `snort -r`. |
| `-r <logfile>` | قراءة ملف لوج ثنائي (أو PCAP) عبر Snort | يسمح بإعادة فحص السجلات المحفوظة وتصفيتها باستخدام **فلاتر BPF** مثل `icmp` أو `tcp` أو `'tcp port 80'`. |
| `-n <count>` | تحديد عدد الحزم المراد معالجتها | يوقف Snort بعد معالجة عدد محدد من الحزم (مثل `-n 10`) لتجنب طباعة آلاف الحزم عند فحص بداية الملف. |

### نقطة مهمة في صلاحيات لينكس (File Ownership)
لأن Snort يعمل بصلاحيات `sudo` لالتقاط الترافيك، تكون الملفات والمجلدات الناتجة مملوكة لـ `root`. لقراءتها بحسابك العادي:
- إما تستخدم `sudo` مع أوامر القراءة، **أو**
- تغيّر ملكية المجلد: `sudo chown username -R directory` (حيث `-R` يطبّق التغيير على المجلد وكل ما بداخله).

### شرح ما فعلناه في التمرين خطوة بخطوة

1. **تسجيل الترافيك بصيغة ASCII (`TASK-6 Exercise`):**
   ```bash
   sudo snort -dev -K ASCII -l .
   # وفي نافذة أخرى:
   ```

### ما هو هذا الوضع ولماذا نستخدمه؟

### شرح الـ Flags وأوضاع التنبيه (`-A`)

| المعامل | الوظيفة | الفائدة العملية |
| :--- | :--- | :--- |
| `-c <conf> -T` | اختبار الإعدادات | التأكد من سلامة القواعد قبل التشغيل الحي. |
| `-N` | تعطيل تسجيل الحزم (Disable logging) | يمنع كتابة ملفات اللوج على القرص مع استمرار عرض المخرجات/التنبيهات في الطرفية—ممتاز للاختبارات دون استهلاك مساحة القرص. |
| `-D` | التشغيل في الخلفية (Daemon mode) | لتشغيل Snort بشكل مستمر أو عبر السكربتات (`ps -ef \| grep snort` لمعرفة PID و`sudo kill -9 <PID>` لإيقافه). لا يُنصح به قبل التأكد من استقرار القواعد. |

## Task 9: هيكلية قواعد Snort (Snort Rule Structure)

كتابة القواعد هي جوهر قوة Snort. كل قاعدة تتكون من جزأين:
1. **رأس القاعدة (Rule Header)** *(إلزامي)*: يحدد الإجراء، البروتوكول، عناوين الـ IP، البورتات، واتجاه الترافيك.
2. **خيارات القاعدة (Rule Options)** *(اختياري من حيث الصياغة، لكنه أساسي لاكتشاف الهجمات بدقة)*: يكتب بين قوسين `(...)` ويفصل بين كل خيار وآخر فاصلة منقوطة `;`.

```text
[Action] [Protocol] [Src IP] [Src Port] [Direction] [Dst IP] [Dst Port] ( [Options]; )
```

### أولًا: مكونات رأس القاعدة (Rule Header)

#### 1. الإجراءات (Actions)
| الإجراء | ماذا يفعل؟ | متى يُستخدم؟ |
| :--- | :--- | :--- |
| `alert` | يُصدر تنبيهًا ويسجّل الحزمة | الاستخدام الأساسي في وضع IDS. |
| `log` | يسجّل الحزمة فقط بدون تنبيه | للتسجيل الصامت والمراجعة اللاحقة. |
| `drop` | يحجب الحزمة ويسجّلها | في وضع IPS للحجب الصامت. |
| `reject` | يحجب الحزمة ويسجّلها وينهي الجلسة (يرسل RST/ICMP) | في وضع IPS عند الرغبة في قطع الاتصال فورًا. |

#### 2. البروتوكولات (Protocols)
يدعم Snort 2 أربعة بروتوكولات فقط في رأس القاعدة: **`ip` و `tcp` و `udp` و `icmp`**.
- **كيف نكتشف بروتوكولات التطبيقات مثل FTP أو HTTP؟** نختار `tcp` في الرأس، ونحدد البورت (`21` أو `80`)، ونفحص محتوى الحزمة داخل الخيارات باستخدام `content`.

#### 3. فلترة العناوين والبورتات (IP & Port Filtering)
- **عنوان مفرد:** `192.168.1.56`
- **نطاق شبكة (CIDR):** `192.168.1.0/24`
- **قائمة عناوين أو بورتات:** `[192.168.1.0/24, 10.1.1.0/24]` أو `[21,23]`
- **النفي والاستثناء (`!`):** `!192.168.1.0/24` أو `!21` (كل شيء ما عدا هذا العنوان أو البورت)
- **نطاق البورتات:**
  - `1:1024` (من بورت 1 إلى 1024)
  - `:1024` (من بورت 0 إلى 1024)
  - `1025:` (من بورت 1025 فما فوق)

#### 4. اتجاه الترافيك (Direction)
- `->` : من المصدر (اليسار) إلى الوجهة (اليمين) فقط.
- `<>` : ثنائي الاتجاه (ذهابًا وإيابًا).
- *(ملاحظة: لا يوجد عامل `<-` في Snort نهائيًا).*

---

### ثانيًا: خيارات القاعدة (Rule Options)

#### أ) الخيارات العامة (General Rule Options)
| الخيار | الوظيفة | ما فائدته؟ |
| :--- | :--- | :--- |
| `msg:"...";` | رسالة التنبيه | توضح للمحلل سبب إطلاق التنبيه فورًا في اللوج أو الطرفية. |
| `sid:<id>;` | رقم تعريفي فريد للقاعدة | `<100` محجوزة للنظام، `100–999,999` للقواعد الجاهزة، `>=1,000,000` لقواعد المستخدم. يجب ألا يتكرر نفس الـ `sid` أبدًا. *(ملاحظة: ورد خطأ مطبعي في الشرح الأصلي بكتابة `100.000.000` في جملة واحدة بينما النطاق الصحيح في الجدول هو `>=1,000,000`)*. |
| `reference:<type>,<id>;` | مرجع خارجي مثل CVE | يربط التنبيه برقم الثغرة أو المصدر لتسريع التحقيق (`reference:cve,CVE-XXXX;`). |
| `rev:<num>;` | رقم المراجعة (Revision) | يحدد عدد مرات تعديل القاعدة. Snort لا يحتفظ بسجل تلقائي للتعديلات، لذا يجب زيادة `rev` يدويًا بعد كل تعديل. |

#### ب) خيارات فحص البيانات (Payload Detection Options)
| الخيار | الوظيفة | ما فائدته؟ |
| :--- | :--- | :--- |
| `content:"...";` | البحث عن نص ASCII (`"GET"`) أو HEX (`"\|47 45 54\|"`) داخل البيانات | يكتشف كلمات أو بايتات محددة داخل الترافيك. حساس لحالة الأحرف افتراضيًا، وتكراره يزيد الدقة لكنه يزيد استهلاك المعالج. |
| `nocase;` | إلغاء الحساسية لحالة الأحرف (Case-insensitive) | يمنع الالتفاف بتغيير الأحرف الكبيرة والصغيرة (`get` بدل `GET`). |
| `fast_pattern;` | تحديد النص ذي الأولوية في البحث المبدئي | افتراضيًا يبدأ Snort بأطول `content`؛ هذا الخيار يجبره على استخدام كلمة محددة أولًا لتسريع الفحص (يعمل غير حساس لحالة الأحرف ويُستخدم مرة واحدة في القاعدة). |

#### ج) خيارات غير مرتبطة بالبيانات (Non-Payload Detection Options)
| الخيار | الوظيفة | ما فائدته؟ |
| :--- | :--- | :--- |
| `id:<num>;` | فحص حقل **IP ID** في ترويسة IP | يفيد في تتبع حزم معينة أو أدوات فحص وتوليد حزم مخصصة. |
| `flags:<flags>;` | فحص أعلام **TCP** (`F`, `S`, `R`, `P`, `A`, `U`) | يكتشف فحوصات المنافذ (مثل SYN scan) أو حالات اتصال محددة (مثل `PA` لـ Push-Ack). |
| `dsize:<range>;` | فحص حجم الـ Payload (`min<>max`, `>100`, `<100`) | مفيد لرصد الحزم الضخمة غير الطبيعية أو القنوات السرية الصغيرة. |
| `sameip;` | رصد الحزم التي يكون فيها `Src IP == Dst IP` | يكتشف هجمات Land Attack والحزم المزورة. |

## Task 10: منطق عمل Snort2 ونقاط مهمة

### 1. المكونات الخمسة الرئيسية في Snort (مسار معالجة الحزمة)
1. **Packet Decoder:** يلتقط الحزم من الواجهة ويفك ترويساتها وتهيئتها للمرحلة التالية.
2. **Pre-processors:** يعيد تجميع الحزم وتطبيعها (مثل تجميع TCP Streams وفك ترميز HTTP) قبل وصولها لمحرك الكشف؛ وهذا يمنع المهاجمين من خداع القواعد عبر تقطيع الحزم أو التلاعب بالترميز.
3. **Detection Engine:** قلب النظام؛ يفحص الحزم المعالجة ويطابقها مع القواعد النشطة.
4. **Logging and Alerting:** يولّد ملفات التنبيه وسجلات الحزم عند تحقق أي قاعدة.
5. **Outputs and Plugins:** يربط المخرجات بأنظمة خارجية (مثل Syslog و MySQL) ويدعم الإضافات المتقدمة.

### 2. أنواع قواعد Snort (Rulesets)
- **Community Rules:** مجانية تمامًا تحت رخصة GPLv2 ولا تحتاج تسجيل.
- **Registered Rules:** مجانية لكنها تتطلب التسجيل، وتصلها قواعد المشتركين بتأخير **30 يومًا**.
- **Subscriber Rules (Paid):** مدفوعة وتُحدّث مرتين أسبوعيًا (الثلاثاء والخميس) لتوفير حماية فورية لأحدث التهديدات.

### 3. أهم أقسام ملف `/etc/snort/snort.conf`

#### Step #1: المتغيرات الشبكية (Network Variables)
- `HOME_NET`: الشبكة المحمية (مثل `192.168.1.1/24` أو `any`).
- `EXTERNAL_NET`: الشبكة الخارجية غير الموثوقة (غالبًا `!$HOME_NET` أو `any`).
- مسارات القواعد: `RULE_PATH` (`/etc/snort/rules`)، و`SO_RULE_PATH`، و`PREPROC_RULE_PATH`.

#### Step #2: إعدادات Decoder ووضع IPS (`DAQ`)
وحدات **DAQ (Data Acquisition)** هي الطبقة المسؤولة عن قراءة/تمرير الحزم، وتتيح التبديل بين المراقبة السلبية والحجب المباشر:
1. `PCAP`: الوضع الافتراضي (Sniffer/IDS).
2. `Afpacket`: أشهر وضع لتشغيل IPS المباشر على لينكس (`config daq: afpacket` و `config daq_mode: inline`).
3. `Ipq`: وضع Inline قديم على لينكس عبر Netfilter (بديل `snort_inline`).
4. `Nfq`: وضع Inline حديث على لينكس عبر Netfilter queue.
5. `Ipfw`: وضع Inline لأنظمة OpenBSD و FreeBSD.
6. `Dump`: وضع مخصص لاختبار التطبيع ووضع Inline.

#### Step #6 و Step #7: المخرجات وتخصيص القواعد
- **Step #6 (Output Plugins):** لتوجيه التنبيهات والسجلات لصيغ أو قواعد بيانات أخرى بدل الطرفية فقط.
- **Step #7 (Customise Ruleset):** تفعيل القواعد عبر `include $RULE_PATH/local.rules` أو إزالة علامة التعليق `#` من أمام أي ملف قواعد ترغب في تشغيله.

> **قاعدة ذهبية:** لا تستبدل ملف `snort.conf` العامل بملف آخر عشوائيًا، بل عدّل بحذر أو استخدم أدوات إدارة القواعد مع أخذ نسخة احتياطية والاختبار بـ `-T`.

## Task 11: الخلاصة وأفضل الممارسات (Conclusion)

### نصائح ذهبية عند العمل على Snort
1. **ابنِ القواعد تدريجيًا:** أضف الخيارات خطوة بخطوة حتى يسهل اكتشاف أي خطأ برمجي أو منطقي.
2. **لا تخترع العجلة من جديد:** طوّر وحسّن القواعد الجاهزة إذا كانت تفي بالغرض.
3. **احفظ نسخة احتياطية دائمًا** من ملفات الإعدادات قبل أي تعديل.
4. **عطّل القاعدة بالتعليق (`#`) بدل حذفها** إذا كانت تعمل جيدًا ولا تحتاجها مؤقتًا.
5. **اختبر أي قاعدة جديدة أولًا** باستخدام `-T` وملفات `.pcap` تجريبية قبل نقلها لبيئة الإنتاج.

## ملخص سريع للأوامر (Cheatsheet)

```bash
# التحقق من النسخة واختبار الإعدادات
snort -V
sudo snort -c /etc/snort/snort.conf -T

# Sniffer Mode
sudo snort -v -i eth0       # عرض ترويسات TCP/IP على eth0
sudo snort -d               # عرض الترويسات + Payload
sudo snort -de              # عرض الترويسات + Payload + عناوين MAC
sudo snort -X               # عرض الحزمة كاملة بالـ HEX و ASCII

# Packet Logger Mode
sudo snort -dev -l .                       # حفظ لوج ثنائي في المجلد الحالي
sudo snort -dev -K ASCII -l .              # حفظ لوج نصي مقسم بمجلدات IP
sudo snort -r snort.log.XXXX -n 10         # قراءة أول 10 حزم من اللوج الثنائي
sudo snort -r snort.log.XXXX 'tcp port 80' # تصفية اللوج بفلتر BPF

# IDS / PCAP / IPS Mode
sudo snort -c /etc/snort/snort.conf -A console                    # تنبيهات فورية على الشاشة
sudo snort -c /etc/snort/snort.conf -A full -l . -r file.pcap     # تحليل PCAP واحد
sudo snort -c /etc/snort/snort.conf -q --pcap-list="a.pcap b.pcap" -A console --pcap-show
sudo snort -c /etc/snort/snort.conf -q -Q --daq afpacket -i eth0:eth1 -A console  # وضع IPS للحجب
```
